# PRD - 빙빙제로

## 1. 제품 정의

빙빙제로는 겨울철 서울 보행자가 이동 전에 결빙 위험 예상 구간을 확인하고,
일반 도보 경로와 위험·계단·경사 구간을 회피하는 추천 도보 경로를 비교하도록
돕는 서비스다.

추천 결과는 실제 결빙 확인이나 안전을 보장하지 않는다. 데이터와 계산 결과의
한계를 명확히 표시하고 사용자가 위험과 추가 시간을 함께 판단하게 한다.

## 2. 해결할 문제

일반 날씨 정보만으로는 실제 이동 경로의 어느 보행 구간이 미끄러울 가능성이
있는지 알기 어렵다. 고령층과 보행약자는 이동 중 위험 구간을 만난 뒤 우회하기가
더 어렵다. 서비스는 위험 정보를 실제 도보 경로 선택과 연결해야 한다.

## 3. 대상 사용자

- 우선 사용자: 고령층, 보행약자
- 확장 사용자: 겨울철 도보 이동을 계획하는 일반 시민
- 대상 지역: 서울 전역

## 4. MVP 범위

### 포함

- 서울 안의 출발지·목적지 선택
- 보행 허용 네트워크의 일반 도보 경로 계산
- 선택 시각의 실제 기상·공간 데이터 조회
- 구간별 결빙 위험 예상
- 결빙·계단·경사 구간을 고려한 추천 도보 경로 계산
- 일반 경로와 추천 경로의 거리·예상시간·추가 예상시간 비교
- 위험 예상 구간 지도 표시
- 실제 과거 예보·관측을 이용한 시연 모드
- 정보 부족, 지역 밖, 경로 없음, 외부 자료 실패 상태 안내

### 제외

- 자동차·대중교통 경로
- 로그인, 계정, 개인 이동 이력 저장
- 실제 안전 보장 또는 사고 감소 효과 주장
- 합성 기상·합성 결빙 데이터로 만든 성공 시연
- 사용자 UI에서의 원시 강수량·내부 점수·특징값·임계값 노출
- 승인 디자인에 없는 화면과 기능의 임의 추가
- 초기 MVP의 이동 중 안내
- 즐겨찾기, 최근 검색, 계정 화면

후속으로 추가한 경로 안내는 선택한 경로의 회전·결빙 예상구간을 화면, 한국어
음성, 지원 기기의 진동으로 전달한다. 현재 시각 경로는 위치 권한을 받아
화면을 보는 동안 안내한다. 경로 단계 미리보기는 위치 권한 없이 제공한다.

결빙 알림 시연은 자주 다니는 길을 알려 준다는 사용 흐름을 검증한다. 사용자가
시연을 켜면 앱 화면에 10분마다 알림을 띄운다. 알림에서 출발지·목적지 입력을
건너뛰고 양재의 실제 과거 기상 재생 결과를 확인할 수 있다. 시연에서 개인 경로나
위치를 저장하지 않는다.

## 5. 핵심 사용자 흐름

1. 사용자가 서비스에 접속한다.
2. 출발지와 목적지를 선택한다.
3. 현재 또는 실제 과거 시각을 선택한다.
4. 서비스가 입력과 서울 범위를 검증한다.
5. 보행 허용 네트워크에서 일반 도보 경로를 계산한다.
6. 선택 시각의 실제 데이터를 조회하고 위험 예상 구간을 계산한다.
7. 위험·계단·경사 구간을 고려한 추천 도보 경로를 계산한다.
8. 지도와 결과 카드에서 경로와 추가 예상시간을 비교한다.
9. 사용자가 경로를 선택하거나 입력을 수정한다.

## 6. 제품 요구사항

| ID | 요구사항 |
|---|---|
| `PRD-001` | 출발지와 목적지는 서울 안의 유효한 좌표여야 한다. |
| `PRD-002` | 일반 경로와 추천 경로는 보행 허용 네트워크에서 계산한다. |
| `PRD-003` | 자동차 전용 또는 보행 금지 차도 간선을 경로에 포함하지 않는다. |
| `PRD-004` | 일반 경로는 거리 기준 최단 도보 경로를 기본으로 한다. |
| `PRD-005` | 위험 예상에는 검증 가능한 실제 데이터만 사용한다. |
| `PRD-006` | 실제 과거 데이터 재생 시 출처와 적용 날짜·시각을 표시한다. |
| `PRD-007` | 합성 데이터로 핵심 기능을 통과시키거나 시연하지 않는다. |
| `PRD-008` | 데이터 부족을 낮은 위험으로 해석하지 않는다. |
| `PRD-009` | 추천 경로가 없으면 이유를 표시하고 가짜 경로를 만들지 않는다. |
| `PRD-010` | 일반·추천 경로 시간은 같은 보행속도와 계산 기준을 사용한다. |
| `PRD-011` | 추가 예상시간은 추천 경로 시간에서 일반 경로 시간을 뺀 값이다. |
| `PRD-012` | 서비스 로직과 데이터 처리는 특정 서울 일부 지역에 하드코딩하지 않는다. |
| `PRD-013` | 내부 강수량, 결빙 점수, 특징값, 임계값은 사용자 UI에 노출하지 않는다. |
| `PRD-014` | 승인된 `DESIGN.md`의 화면 구조와 정보 노출을 따른다. |
| `PRD-015` | 위험은 색상만이 아니라 아이콘 또는 문구와 함께 전달한다. |
| `PRD-016` | 추천이 실제 결빙 확인 또는 통행 안전 보장을 뜻하지 않음을 안내한다. |
| `PRD-017` | 위치와 경로 데이터는 요청 처리에 필요한 범위만 사용한다. |
| `PRD-018` | 복수의 실제 과거 시연 시나리오를 지원한다. |
| `PRD-019` | 각 시연 경로에는 좌회전 또는 우회전이 한 번 이상 포함되어야 한다. |
| `PRD-020` | 시연 장소는 실제 시민이 이용할 가능성이 있는 장소 조합이어야 한다. |

## 7. 상태와 예외

| 상태 | 사용자 처리 |
|---|---|
| 입력 오류 | 잘못된 출발지·목적지와 수정 방법 안내 |
| 서울 지역 밖 | 지원 지역이 서울임을 안내 |
| 보행망 연결 실패 | 해당 위치에서 도보 경로를 만들 수 없음을 안내 |
| 데이터 부족 | 위험을 낮음으로 표시하지 않고 자료 부족 안내 |
| 데이터 갱신 실패 | 마지막 갱신 시각과 재시도 안내; 오래된 값을 현재값처럼 표시 금지 |
| 일반 경로 없음 | 경로 결과를 만들지 않고 입력 수정 안내 |
| 추천 경로 없음 | 일반 경로와 별개로 추천 불가 사유 안내 |
| 계산 실패 | 경로·시간 임의 표시 금지, 재시도 안내 |

## 8. UI 정보 경계

사용자에게 보여줄 정보는 승인된 `DESIGN.md`가 최종 결정한다. 제품 수준에서
필요한 정보는 다음과 같다.

- 출발지·목적지
- 선택 시각과 실제 데이터 기준 시각
- 일반 경로와 추천 경로
- 위험 예상 구간
- 예상시간과 추가 예상시간
- 자료 상태와 필요한 한계 안내

다음은 내부 로직에만 둔다.

- 원시 강수량과 적설량
- 내부 결빙 점수와 임계값
- 모델 특징값과 가중치
- 공급자별 원본 응답
- 디버그·캐시 정보

## 9. 실제 과거 시연 시나리오

현재 날씨에서 결빙 조건을 보여주기 어렵다면 실제 과거 예보·관측을 재생한다.
정확한 시나리오는 `TASKS.md`에서 실제 자료와 보행망을 확인한 뒤 확정한다.

각 시나리오는 다음을 갖는다.

- KST 날짜와 시각
- 출발지와 목적지의 실제 장소명·좌표
- 데이터 출처와 조회 시각
- 실제 이용 가능성이 있는 이동 목적
- 좌회전 또는 우회전 포함 확인
- 모든 경로 간선의 보행 허용 확인
- 일반 경로의 위험 예상구간과 추천 경로 차이

## 10. 성공 기준

- 서울의 서로 떨어진 복수 생활권에서 경로 요청이 동작한다.
- 모든 결과 경로가 보행 허용 간선으로만 구성된다.
- 실제 데이터가 위험 계산에 사용되고 출처를 추적할 수 있다.
- 위험 입력이 추천 경로 선택에 실제로 반영된다.
- 일반·추천 경로의 시간과 추가시간 계산이 일치한다.
- 승인 디자인과 UI가 일치한다.
- 내부 계산값이 사용자 화면에 노출되지 않는다.
- 정보 부족과 실패 상태에서 가짜 결과가 생성되지 않는다.
- 실제 과거 시연 시나리오가 재현 가능하다.
