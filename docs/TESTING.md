# TESTING - 빙빙제로

## 1. 목적

테스트는 화면이 보이는지만 확인하지 않는다. 실제 데이터가 경로 계산에
반영되는지, 추천 경로가 보행로만 사용하는지, 서울 일부에 하드코딩되지
않았는지, 승인 디자인과 정보 경계가 지켜지는지를 검증한다.

## 2. 테스트 원칙

- 핵심 기능 테스트에 합성 기상·결빙 데이터를 사용하지 않는다.
- 실제 외부 자료를 사용하는 통합 테스트와 순수 계산 단위 테스트를 구분한다.
- 단위 테스트의 작은 구조 fixture는 허용하지만 실제 시연 데이터로 가장하지 않는다.
- 실제 과거 데이터는 출처·조회 시각·적용 시각을 기록한다.
- 테스트를 실행하지 않았으면 `NOT RUN`으로 보고한다.
- 실패한 테스트를 삭제하거나 조건을 약화해 통과시키지 않는다.
- 외부 API 장애와 제품 결함을 구분해 기록한다.

## 3. 과거에 발생한 실패와 필수 회귀 테스트

| ID | 과거 실패 | 반드시 검증할 항목 |
|---|---|---|
| `REG-001` | 실제 데이터 대신 합성 데이터 사용 | 핵심 시연 입력의 출처·기준 시각·실제 응답 증거 |
| `REG-002` | 제공한 UI와 다르게 구현 | 승인 `DESIGN.md`와 화면 구조·상태·노출 필드 비교 |
| `REG-003` | 보도 대신 차도가 포함된 경로 추천 | 결과의 모든 간선이 보행 허용인지 검사 |
| `REG-004` | 강수량·결빙 점수 등 내부 정보를 UI에 노출 | public response와 렌더링 텍스트에 내부 필드 부재 확인 |
| `REG-005` | 서울 일부 지역만 구현 | 서로 떨어진 복수 생활권에서 같은 흐름 검증, 고정 좌표 탐지 |
| `REG-006` | 서로 다른 경로 엔진을 비교 | 두 경로가 같은 OSM 보행 그래프·Dijkstra·1m/s 산식 사용 |
| `REG-007` | 검증 없이 다른 기술로 대체 | TMAP 경로·ORS·FastAPI·학습 모델이 승인 없이 추가되지 않음 |

## 4. 요구사항 인수 테스트

### `AT-001` 실제 데이터 추적

**Given** 실제 현재 또는 과거 시나리오가 있고
**When** 위험 계산을 실행하면
**Then** 각 입력의 공급자, 기준 시각, 좌표/구역, 상태를 추적할 수 있다.

합격 조건:

- 합성 기상값이 핵심 경로에 없다.
- 실제 과거 재생은 `HISTORICAL_REPLAY`로 표시된다.
- 자료 누락을 0값으로 채우지 않는다.

### `AT-002` 보행 전용 일반 경로

**Given** 서울 안의 출발지와 목적지가 있고
**When** 일반 경로를 계산하면
**Then** 경로를 구성하는 모든 간선이 보행 허용이다.

합격 조건:

- 자동차 전용·고속도로·보행 금지 간선이 0개다.
- 자동차 도로 중심선을 별도 보행 way처럼 사용한 간선이 0개다.
- 간선별 허용 근거를 확인할 수 있다.
- 연결 불가 시 가짜 직선 경로를 만들지 않는다.

### `AT-003` 위험 반영 추천 경로

**Given** 일반 경로에 실제 데이터로 판정한 회피 대상이 있고
**When** 추천 경로를 계산하면
**Then** 추천 경로가 선택한 회피 정책을 만족한다.

합격 조건:

- 추천 경로의 회피 대상 간선 수가 정책과 일치한다.
- 추천 경로도 모든 간선이 보행 허용이다.
- 일반·추천 경로가 같은 타일 버전과 그래프를 사용한다.
- 연결이 끊기면 추천 없음 상태다.

### `AT-004` 시간 계산

**Given** 일반 경로와 추천 경로가 있고
**When** 시간을 계산하면
**Then** 두 경로가 같은 보행속도와 산식을 사용한다.

합격 조건:

- `추가시간 = 추천시간 - 일반시간`이다.
- 단위가 모두 seconds로 일치한다.
- 경로가 없을 때 시간값을 만들지 않는다.

### `AT-005` UI 디자인 일치

**Given** 승인된 `DESIGN.md`가 있고
**When** 결과 화면을 렌더링하면
**Then** 정보 구조, 문구, 상태, 컴포넌트 배치가 디자인과 일치한다.

`DESIGN.md`가 없으면 이 테스트는 `BLOCKED`이며 최종 UI를 완료 처리하지 않는다.

### `AT-006` 내부 정보 비노출

**Given** 서버가 원시 기상값과 내부 위험 계산값을 사용하고
**When** API 응답과 UI를 확인하면
**Then** 승인 디자인에 없는 내부 값이 사용자에게 노출되지 않는다.

검색 대상 예:

- raw precipitation/snowfall
- numeric risk score
- feature weights
- thresholds
- provider debug payload
- cache key와 내부 오류 stack

### `AT-007` 서울 전역 범위

**Given** 서울의 서로 떨어진 복수 생활권 시나리오가 있고
**When** 같은 경로 흐름을 실행하면
**Then** 지역별 하드코딩 없이 동일 규칙으로 처리된다.

합격 조건:

- 특정 역·동·좌표가 소스의 정상 경로에 하드코딩되지 않는다.
- 서울 경계 내부의 서로 다른 시나리오가 동작한다.
- 범위 밖 좌표는 명확히 거부한다.

### `AT-008` 과거 시연 시나리오

각 `TASKS.md` 시나리오는 다음을 만족한다.

- 실제 과거 데이터 출처가 있다.
- 날짜·시각·출발지·목적지가 고정되어 재현 가능하다.
- 실제 이용 가능성이 있는 장소 조합이다.
- 경로에 좌회전 또는 우회전이 한 번 이상 포함된다.
- 모든 경로 간선이 walk-only 검증을 통과한다.
- 적어도 한 시나리오에서 위험 반영 전후 경로 차이를 보여준다.

### `AT-009` 자료 부족

**Given** 위험 판단에 필요한 실제 자료가 부족하고
**When** 요청을 처리하면
**Then** 낮은 위험이 아니라 자료 부족 상태를 반환한다.

### `AT-010` 추천 경로 없음

**Given** 회피 대상 제거 후 보행망 연결이 끊기고
**When** 추천 경로를 계산하면
**Then** 추천 불가 사유를 반환하며 geometry와 시간을 만들지 않는다.

### `AT-011` 보행 타일 무결성

**Given** Geofabrik PBF에서 생성한 서울 타일과 `index.json`이 있고
**When** 앱이 필요한 타일을 로드하면
**Then** 출처·기준 시각·형식 버전·SHA-256을 검증한다.

합격 조건:

- 누락·변조·형식 불일치 타일을 사용하지 않는다.
- 원본 PBF와 비밀키를 저장소에 커밋하지 않는다.
- OSM attribution과 ODbL 링크가 사용자 지도에 표시된다.

### `AT-012` `risk-rule-v1`

**Given** 선택 정각과 직전 6시간의 실제 기상 자료가 있고
**When** 위험을 계산하면
**Then** `0°C 이하`와 양의 수분 근거가 함께 확인된 구역에서만 재결빙 조건을 만든다.

합격 조건:

- 확인된 0mm와 누락값이 구분된다.
- 필수 자료 누락은 `UNKNOWN`이다.
- 재결빙 구역의 검증된 실외 보행교·건물 그늘 간선만 P0 위험 간선이다.
- 규칙 버전이 `risk-rule-v1`로 기록된다.
- 원시 기상값과 임계값은 public response와 UI에 없다.

## 5. 테스트 계층

| 계층 | 대상 | 외부 연결 |
|---|---|---|
| 단위 | 거리·시간·상태 변환·경로 후검증 | 없음 |
| 계약 | 요청·응답·오류·필드 비노출 | 없음 또는 고정 fixture |
| 통합 | 실제 공급자 어댑터·정규화·과거 조회 | 실제 외부 연결 |
| 종단 | 실제 과거 시나리오의 입력부터 UI까지 | 실제 또는 검증된 재생 자료 |
| 수동 | 디자인·접근성·지도 표현·시연 흐름 | 브라우저 |

## 6. 외부 데이터 테스트 기록

각 실행에서 다음을 남긴다.

```text
테스트 ID:
실행 시각(KST):
시나리오 ID:
공급자:
요청한 데이터 기준 시각:
응답 상태:
결측 필드:
보행망 버전/조회 시각:
결과:
PASS/FAIL/BLOCKED:
비고:
```

API 키와 원본 민감 응답은 기록하지 않는다.

## 7. 기능 완료 전 체크리스트

- [ ] 변경된 요구사항에 대응하는 테스트가 있다.
- [ ] 관련 단위·계약 테스트가 통과한다.
- [ ] 필요한 실제 데이터 통합 테스트를 실행했다.
- [ ] 경로 간선 walk-only 후검증이 통과한다.
- [ ] 일반·추천 경로가 동일한 보행 타일과 그래프를 사용한다.
- [ ] 타일 SHA-256과 출처가 검증된다.
- [ ] 서울 일부 하드코딩이 없다.
- [ ] 내부 계산값이 public API와 UI에 없다.
- [ ] 실패·자료 부족·추천 없음 상태를 구분한다.
- [ ] 테스트 결과를 `TASKS.md`에 반영했다.
- [ ] 기능 단위 커밋과 푸시 전에 실패를 보고했다.

## 8. 최종 시연 합격 기준

- 복수의 실제 과거 시나리오가 재현된다.
- 시나리오마다 좌회전 또는 우회전이 한 번 이상 포함된다.
- 위험 예상구간이 지도 위치와 일치한다.
- 위험이 추천 경로 계산에 실제로 반영된다.
- 일반·추천 경로와 추가시간이 일치한다.
- 차도·자동차 전용 간선이 결과에 없다.
- 일반·추천 경로가 같은 보행 그래프와 `1m/s` 산식을 사용한다.
- 승인 디자인과 결과 UI가 일치한다.
- 원시 강수량·내부 결빙 점수는 화면에 없다.
- 정보 부족과 실패에서 거짓 결과가 없다.
- 서울의 서로 다른 생활권에서 같은 기능이 동작한다.

## 9. 해커톤 검증 결과

- 실제 TMAP 장소 검색과 보관한 Open-Meteo AIFS 예보로 양재·혜화·시청을
  브라우저에서 재현했다.
- 양재 결과에서 결빙 위험 예상구간과 두 경로를 표시한다. 기상 호출 실패를
  재현하면 일반 경로만 표시하고 안전 경로의 평가를 보류한다.
- 모바일 360px 화면의 200% 글자 크기, 검색 화면의 키보드 포커스와 입력 라벨을
  검증했다.
- 개발 서버의 `.dev.vars` 및 `staticdata` 접근 차단, 배포 빌드의 비밀 파일
  제외, Git 인덱스의 비밀값 미포함을 확인했다.
- Cloudflare 배포 환경의 실연과 Android TalkBack·Switch Access 실기기 검증은
  미실행이다.

## 10. 후속 경로 안내 검증

- 실제 양재 시연 경로로 경로 단계 보기, 다시 듣기, 안내 종료와 포커스 복귀를
  브라우저에서 확인한다.
- 자동 테스트에서는 브라우저 위치·음성·진동 API를 대체해 한국어 문장과 진동
  패턴 전달, 위험 경고 중복 방지, 위치 불확실·권한 거부 처리, 감시 종료를
  검증한다. 실제 기기에서 소리와 진동이 발생하는지 확인하는 항목은 별도다.

## 11. 결빙 알림 시연 검증

- 서버 자동 테스트에서는 기기 등록, 즉시 요청, 10분·20분 도달, 재시작 이후
  상태 보존, 예약 중복 제거, 끄기, 자동 종료를 검증한다.
- 브라우저 자동 테스트에서는 서비스 워커의 시스템 알림 표시, 360px·200%
  화면, 알림 링크에서 양재 경로와 실제 기상 기준·출처를 확인한다.
- 휴대폰 확인 절차는 홈 화면 설치(아이폰) → 메뉴 → 알림 설정 → 기기 알림 켜기 → 양재 예시 알림 보내기 →
  잠금화면에서 시연 문구 확인 → 알림을 눌러 경로 열기다. 앱을 닫고 10분 주기의
  예약 알림과 끄기 동작도 확인한다.

## 12. 지도 중심 모바일 화면 검증

- 첫 화면의 주요 동작은 목적지 검색이다. 지도와 48px 이상의 조작 버튼을
  제공한다. 지도 타일이 실패해도 검색으로 이동할 수 있어야 한다.
- 홈에서 알림·시연 기능과 고정 추천 장소가 노출되지 않아야 한다. 메뉴를
  열면 제목에 포커스가 이동하고 Escape 후에는 메뉴 버튼으로 돌아와야 한다.
- 360px 너비와 200% 글자에서 지도, 검색, 메뉴, 결과 카드의 가로 넘침을
  확인한다. 경로 결과를 지도 없이 읽을 수 있는 요약 진입도 확인한다.
- 최근 화면 흐름에서 확인 화면의 `여기로 길찾기`와 이동 안내 화면 상단의
  `다시 듣기`, 종료 후 경로 결과 및 버튼 초점 복귀를 확인한다.
