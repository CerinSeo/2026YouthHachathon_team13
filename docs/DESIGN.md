# DESIGN.md - 빙빙제로 UI 디자인 명세 초안

> 상태: 프로젝트 반입본 - 세부 결정 항목 검토 필요
> 작성일: 2026-11-21
> 적용 대상: 모바일 우선 웹/Android UI
> 기준 스타일: 예시 이미지의 겨울·지도 중심 분위기 + Material Design 3

## 1. 목적

빙빙제로는 고령층, 저시력 사용자, 보행약자, 인지·학습에 어려움이 있는
사용자까지 출발지 선택, 경로 비교, 위험 이해를 무리 없이 완료할 수 있어야 한다.

디자인의 우선순위는 다음과 같다.

1. 정보 이해와 안전한 의사결정
2. 큰 글자와 명확한 조작
3. 보행 경로와 위험 예상구간의 구별
4. 짧고 예측 가능한 사용자 흐름
5. 예시 이미지의 밝고 친근한 겨울 분위기
6. 장식보다 접근성·성능·지도 가독성

## 2. 디자인 원칙

### 2.1 한 화면에 하나의 주요 목적

- 홈: 목적지 검색 시작
- 검색: 장소 선택
- 확인: 출발지·목적지 확인
- 결과: 두 경로와 추가시간 비교
- 상세: 위험 예상구간의 의미 확인
- 오류: 문제를 이해하고 다음 행동 선택

화면마다 가장 중요한 기본 동작은 하나만 Filled Button으로 강조한다.

### 2.2 사용자가 기억하지 않아도 되는 흐름

- 현재 단계, 선택한 출발지·목적지, 선택 시각을 화면에 유지한다.
- 앞 화면의 정보를 기억해야만 다음 행동을 할 수 있게 만들지 않는다.
- 뒤로가기, 입력 수정, 다시 검색을 항상 찾기 쉬운 위치에 둔다.
- 같은 기능은 모든 화면에서 같은 이름과 아이콘을 사용한다.

### 2.3 색상만으로 의미를 전달하지 않음

- 결빙 위험: 파란색 + 눈꽃 아이콘 + 선 패턴 + 텍스트 라벨
- 목적지: 주황/빨강 + 핀 모양 + 장소명
- 오류: 빨강 + 오류 아이콘 + 원인·해결 문장
- 선택 상태: 색상 + 아이콘/테두리/라벨 변화

### 2.4 안전을 보장하지 않는 언어

- 결빙 위험 예상구간 등을 고려한 경로의 화면 이름은 `안전 경로`로 통일한다.
- `결빙 구간` 대신 `결빙 위험 예상구간`을 기본 표현으로 사용한다.
- `AI가 안전한 길을 안내` 대신 `기상·환경 자료를 바탕으로 위험 예상구간을
  고려한 경로를 안내`라고 표현한다.
- 결과 화면에 `결빙 위험 예상구간을 고려한 경로예요. 실제 노면 상태에 따라 통행 위험이 달라질 수 있어요.`를 표시한다.

### 2.5 내부 계산과 사용자 정보 분리

사용자에게 필요한 결과만 보여준다.

표시:

- 위험 예상구간
- 안전 경로
- 일반 경로와 비교한 추가 예상시간
- 자료 기준 시각
- 현재/과거 기상 재생 여부
- 자료 부족·경로 없음·계산 실패

표시하지 않음:

- 원시 강수량·적설량
- 내부 결빙 점수
- 모델 특징값·가중치·임계값
- 공급자별 원본 응답
- 캐시·디버그 정보

## 3. 예시 이미지에서 가져올 시각 언어

### 3.1 채택

- 밝은 눈·하늘 계열의 차가운 파랑 팔레트
- 짙은 남색의 굵은 제목
- 파란색 안전 경로와 눈꽃 위험 마커
- 지도 위 흰색 부유 카드와 하단 결과 시트
- 큰 예상시간 숫자와 짧은 보조 설명
- 둥근 검색창, 카드, 버튼
- 현재 위치는 파란 원, 목적지는 따뜻한 색 핀으로 구분
- 이동 안내에서 큰 방향 아이콘과 짧은 문장 사용
- 위험 상세와 오류를 별도 surface로 분리하며 설정 surface는 P1에서만 추가

### 3.2 접근성을 위해 수정

- 옅은 파란색 텍스트는 더 짙게 조정한다.
- 작은 12px 수준의 보조 문구는 기본 14sp 이상으로 확대한다.
- 화면 전체의 장식용 눈꽃·그라디언트는 줄이고 접근성 트리에서 제외한다.
- 지도와 경로의 의미를 색만으로 구분하지 않는다.
- 지도만 제공하지 않고 경로 요약과 위험구간 목록을 함께 제공한다.
- 투명도와 그림자만으로 카드 경계를 표현하지 않는다.
- 하단 버튼과 검색 결과 행의 터치 영역을 최소 48dp로 보장한다.

## 4. Material 3 적용 원칙

- 정적 Material 3 color roles를 사용한다.
- 핵심 semantic color는 dynamic color로 변경하지 않는다.
- `primary`, `onPrimary`, `surface`, `onSurface`처럼 의도된 색상 쌍을 유지한다.
- 강조 수준은 과도한 그림자보다 surface container의 tonal 차이로 만든다.
- Filled Button은 화면당 하나의 주요 동작에 사용한다.
- Outlined Button은 취소, 재검색, 보조 동작에 사용한다.
- Assist Chip은 현재/과거 재생, 자료 상태 같은 짧은 상태에 사용한다.
- Modal Bottom Sheet는 경로 상세와 위험 상세에 사용한다.
- Snackbar는 되돌릴 수 있는 경미한 알림에만 사용한다.
- 중요한 오류와 안전 경로를 찾지 못한 상태는 닫히지 않는 카드 또는 dialog로 제공한다.

## 6. 타이포그래피

### 6.1 글꼴

```text
Noto Sans KR, Pretendard, Roboto, system-ui, sans-serif
```

- Android에서는 시스템 한글 글꼴과 Material typography를 우선한다.
- 모든 텍스트 크기는 `sp`로 구현한다.
- 사용자 글꼴 크기 설정을 무시하거나 고정 px로 변환하지 않는다.
- 글자 크기 200%에서도 텍스트가 잘리지 않고 reflow되어야 한다.

### 6.2 타입 스케일

| Token | 크기/행간 | 굵기 | 사용 |
|---|---|---|---|
| `displaySmall` | `36sp / 44sp` | 700 | 예상시간 등 한 화면의 핵심 숫자 |
| `headlineLarge` | `32sp / 40sp` | 700 | 홈 핵심 메시지 |
| `headlineMedium` | `28sp / 36sp` | 700 | 결과 제목, 중요한 오류 |
| `titleLarge` | `22sp / 30sp` | 700 | 화면 제목 |
| `titleMedium` | `18sp / 26sp` | 700 | 카드·sheet 제목 |
| `bodyLarge` | `17sp / 26sp` | 400 | 기본 본문, 주요 설명 |
| `bodyMedium` | `15sp / 23sp` | 400 | 보조 설명 |
| `labelLarge` | `16sp / 22sp` | 700 | 버튼, 중요 chip |
| `labelMedium` | `14sp / 20sp` | 500 | 탭, 상태, 지도 라벨 |

- 사용자에게 보이는 텍스트는 14sp 미만으로 만들지 않는다.
- 긴 문장은 한 줄 24~36자 내외를 목표로 나누고 3줄을 넘기지 않는다.
- 숫자와 단위는 붙여 읽히게 하고 의미 단위로 묶는다. 예: `14분`, `약 3분 추가`.
- ALL CAPS와 지나친 자간을 사용하지 않는다.

## 7. 간격·형태·elevation

### 7.1 간격 토큰

```text
space-1: 4dp
space-2: 8dp
space-3: 12dp
space-4: 16dp
space-5: 24dp
space-6: 32dp
space-7: 40dp
```

- 화면 좌우 기본 padding: `20dp`
- 큰 글자 모드 또는 폭 360dp 미만: `16dp`
- 카드 내부 padding: `16~20dp`
- 서로 다른 터치 대상 사이 여백: 최소 `8dp`

### 7.2 Shape tokens

| Token | radius | 사용 |
|---|---|---|
| `shapeSmall` | `8dp` | 작은 chip·badge |
| `shapeMedium` | `12dp` | input, list container |
| `shapeLarge` | `20dp` | 카드, dialog |
| `shapeExtraLarge` | `28dp` | bottom sheet, 주요 부유 카드 |
| `shapeFull` | `999dp` | 버튼, search bar, 원형 control |

### 7.3 Elevation

- 기본 surface: 0
- 검색창·지도 control: level 1
- 결과 카드·bottom sheet: level 2
- dialog: level 3
- 그림자는 약하게 사용하고 tonal surface와 outline으로 경계를 보강한다.

## 8. 컴포넌트 규격

### 8.1 공통 터치 대상

- 모든 상호작용 영역: 최소 `48dp × 48dp`
- 주요 CTA 높이: `56dp`
- 검색 결과 행: 최소 `64dp`
- 지도 control: 시각 크기 `40dp`, 터치 영역 `48dp`
- icon-only button은 접근성 이름을 반드시 제공한다.

### 8.2 버튼

- Filled Button: `primary` / `onPrimary`, 높이 56dp, radius full
- Outlined Button: 투명 surface, `outline` 1dp, 높이 56dp
- Tonal Button: `secondaryContainer` / `onSecondaryContainer`
- 버튼 텍스트는 행동 결과를 말한다. 예: `경로 비교하기`, `다시 검색하기`.
- `확인`, `계속`처럼 맥락 없는 라벨은 dialog 이외에는 피한다.
- loading 중 버튼을 단순히 비활성화하지 말고 진행 상태와 취소 가능 여부를 알린다.

### 8.3 Search Bar

- 높이 56dp 이상
- placeholder만 쓰지 않고 접근성 label `목적지 검색` 제공
- 지우기 버튼은 `검색어 지우기`로 읽힌다.
- 장소 검색 화면에는 직접 검색한 결과를 표시한다.
- 현재 위치 사용은 별도 명시적 버튼으로 제공한다.

### 8.4 List Item

- 전체 행이 하나의 터치 대상이다.
- 장소명은 `bodyLarge` 또는 `titleMedium`.
- 주소는 `bodyMedium`이며 최대 2줄.
- 같은 행에 `선택` 버튼을 중복 배치하지 않고 행 자체를 선택 가능하게 하는 방식을
  우선한다. 별도 버튼이 있으면 포커스 중복을 피한다.

### 8.5 Cards

- 카드 제목, 핵심 값, 설명, 동작 순서를 유지한다.
- 정보 카드 전체를 클릭 가능하게 만들 때 명확한 affordance를 제공한다.
- 투명 glass 효과는 사용하지 않는다. 지도 위 surface는 최소 94% 불투명으로 한다.

### 8.6 Bottom Sheet

- collapsed 상태에서도 예상시간, 추가시간, 기본 CTA가 보인다.
- drag gesture 외에 `상세 펼치기/접기` 버튼을 제공한다.
- 최대 글자 크기에서 sheet 내부가 스크롤되며 CTA가 가려지지 않는다.
- 지도와 sheet의 포커스 순서를 명확히 분리한다.

### 8.7 Dialog와 오류 카드

- 제목은 문제를 바로 설명한다.
- 본문은 원인과 사용자가 할 수 있는 행동을 짧게 안내한다.
- 주요 동작은 `다시 검색하기`, 보조 동작은 `출발지 수정`처럼 구체적으로 쓴다.
- 중요한 오류는 자동으로 사라지지 않는다.

### 8.8 Navigation Bar

- MVP에서 실제로 존재하는 최상위 목적지만 넣는다.
- 아이콘과 텍스트 라벨을 함께 사용한다.
- 선택 상태는 색 + filled icon/indicator + 라벨로 표현한다.
- 로그인 없는 MVP에서는 `내 정보` 또는 계정 화면을 만들지 않는다.
- 즐겨찾기·최근 검색이 구현되지 않으면 navigation 항목도 노출하지 않는다.

## 9. 지도 디자인

### 9.1 시각 계층

1. 안전 경로
2. 위험 예상구간
3. 출발지·목적지
4. 일반 경로
5. 배경 지도

배경 지도는 saturation과 label contrast를 낮춰 앱 경로가 우선 보이게 한다.

### 9.2 경로 표현

- 안전 경로: 6dp solid `routeRecommended`
- 일반 경로: 4dp dashed `routeNormal`
- 두 경로가 겹치면 안전 경로를 위에 두고 분기 지점에 라벨을 제공한다.
- 위험 예상구간: 안전 경로와 일반 경로 위에 7dp pattern overlay와 눈꽃 marker를 사용한다.
- 경로 선택 상태는 외곽 halo와 굵기 변화로 표현한다.

### 9.3 지도 대체 정보

지도만으로 핵심 정보를 전달하지 않는다.

- 경로 카드에 거리·시간·추가시간을 텍스트로 제공
- 위험 예상구간 수와 위치 설명 제공
- 필요하면 단계별 이동 방향 목록 제공
- TalkBack 탐색 시 지도 전체를 수백 개 marker로 읽지 않고 요약 → 목록 순서로 제공
- map marker에는 장소명 또는 위험구간 라벨 제공

### 9.4 지도 조작

- 확대·축소·현재 위치 버튼은 최소 48dp touch target
- pinch만이 아니라 +/− 버튼 제공
- 위치 선택은 지도 tap 외에 검색·목록 방식도 제공
- 지도 drag가 페이지 뒤로가기나 bottom sheet drag와 충돌하지 않게 한다.

## 10. 화면별 명세

### 10.1 홈

- 실제 서울 지도 위의 상단 검색창에서 서비스명과 `어디로 가세요?`를 함께 표시한다.
  하단 시트에서도 `현재 위치에서 출발하기`와 목적지 검색을 제공한다.
- 배너의 Display P3 원본을 sRGB로 변환한 키 컬러 `#1F83FF`를 지도 경로와
  아이콘에 사용한다. 흰 글자와 함께 쓰는 버튼·안내 띠에는 `#0056C5`를 적용한다.
- 지도에서 확대·축소와 현재 위치 보기를 제공한다. 위치 권한은 사용자가 현재 위치
  버튼을 선택했을 때 요청한다.
- 알림 설정·예시 알림·과거 시연 경로는 상단 메뉴 안의 접힌 항목에서 열 수 있다.
  메뉴를 열면 제목으로 초점이 이동하며, `닫기` 또는 Escape로 닫으면 버튼으로 돌아온다.

### 10.2 장소 검색

- 검색창과 결과 목록을 지도 위에 배치한다. 결과 목록이 길면 목록 안에서 스크롤할 수 있다.
- `출발지 · 현재 위치` 같은 현재 상태를 텍스트로 제공한다.
- 결과는 장소명, 주소, 유형을 일관되게 표시한다.
- 기본 검색 화면에는 검색과 지도 선택을 제공한다. 조회한 결과가 있을 때 목록을 표시한다.
- 결과가 없으면 철자 확인과 지도에서 선택하기를 제안한다.

### 10.3 목적지 확인

- 상단에 목적지를 표시하고 지도에 선택한 장소를 표시한다.
- 모바일에서는 지도를 가리지 않는 스크롤 가능한 하단 시트에 장소명·주소·출발지
  정보를 제공한다. 넓은 화면에서는 지도 옆에 배치한다.
- 주요 동작은 `여기로 길찾기`다. 기상 시각은 하단의 상세 항목에서 수정할 수 있다.
- 출발지 변경은 보조 동작으로 제공한다.

### 10.4 경로 결과

- 상단에는 출발지 → 목적지를 표시한다.
- 지도에는 일반 경로, 안전 경로, 위험 예상구간을 구분해 표시한다.
- bottom sheet 첫 화면에는 다음만 우선 표시한다.
  - `안전 경로`
  - 예상시간
  - 추가 예상시간
  - 위험 예상구간 수
  - 자료 기준 시각 또는 `과거 기상 재생` badge
- `경로 자세히 보기`에서 거리와 시간을 확인한다. 현재 시각 경로에는
  `안내 시작`, 모든 결과에는 `경로 단계 보기`를 제공한다.
- 안전 경로 이름과 함께 2.4절의 노면 상태 안내를 표시한다.

### 10.5 이동 안내

초기 P0 이후 승인된 기능이다. 선택한 경로에 있는 좌·우회전, 결빙 위험 예상구간,
목적지 접근을 순서대로 안내한다.

- 다음 단계와 그 단계까지의 대략적인 거리를 큰 글자로 제공하고 지도도 유지한다.
- 이동 안내에서는 현재 지시와 `다시 듣기`를 지도 위에 배치한다. 신뢰할 수 있는 위치를
  받은 뒤 하단 시트에 남은 거리와 예상시간을 표시하고, `안내 종료`를 제공한다.
- 음성은 브라우저의 한국어 TTS로 재생한다. 브라우저가 지원하는 경우 회전과 결빙
  예상구간에 각각 다른 진동을 사용한다. 두 출력을 각각 끌 수 있다.
- `다시 듣기`와 `안내 종료`를 제공한다. 과거·미래 경로는 위치 권한 없이
  단계별 미리보기를 제공한다.
- 현재 시각 경로의 위치 안내는 사용자가 시작한 뒤 화면이 열려 있는 동안 동작한다.
  좌표는 브라우저에서 처리하고 위치가 불확실하면 방향 대신 상태를 안내한다.
- 화면을 떠나거나 안내를 종료하면 위치 확인과 재생을 중단한다. 해당 경로에
  결빙 위험 자료가 부족하면 기존 자료 부족 상태를 유지한다.

### 10.6 위험 정보 상세

표시:

- `결빙 위험 예상구간 안내`
- `기상·환경 자료를 바탕으로 위험 가능성이 높게 예상됩니다.`
- 자료 기준 시각
- 안전 경로의 노면 상태 안내

표시하지 않음:

- 강수량 수치
- 내부 결빙 점수
- 임계값과 특징값
- 모델 디버그 정보

### 10.7 안전 경로 없음·자료 부족

문구 예:

```text
안전 경로를 찾지 못했어요

현재 조건에서 위험 예상구간을 피하는 도보 경로를 찾지 못했습니다.
출발지나 목적지를 바꾸어 다시 검색해 주세요.
```

자료 부족은 별도 문구를 사용한다.

```text
위험 정보를 계산할 자료가 부족해요

위험을 낮음으로 판단하지 않았습니다. 잠시 후 다시 시도해 주세요.
```

### 10.8 설정

P1 기능이다. 아래 항목이 실제 동작하기 전에는 P0에서 설정 진입점을 노출하지 않는다.

- 글자 크기: 시스템 설정을 따르며 앱 내 `기본/크게/매우 크게` 보조 선택 제공 가능
- 음성 안내 on/off
- 햅틱 안내 on/off
- 애니메이션 줄이기
- 고대비 지도 표시
- 앱 정보와 데이터 기준 안내

설정은 기본 사용자 흐름을 막지 않는다.

### 10.9 즐겨찾기·최근 검색

P1 기능이다.

- 로그인 없이 기기 로컬에만 저장한다.
- 저장 여부와 삭제 방법을 설명한다.
- 탭 선택 상태를 색상과 indicator로 함께 표시한다.
- 기능을 구현하지 않았다면 화면과 navigation 항목을 노출하지 않는다.

### 10.10 잠금화면 결빙 알림 시연

- 홈의 `메뉴 → 알림 설정`에서 `기기 알림 켜기`를 눌러 권한을 허용한 기기에 발송한다. 아이폰은
  Safari에서 홈 화면에 추가해 앱을 연 뒤 켠다.
- 켠 시각 기준 10분 간격으로 최대 6건을 발송한다. `양재 예시 알림 보내기`는 별도의
  푸시를 즉시 요청한다. `반복 알림 끄기`로 이후 발송을 취소한다.
- 제목은 `[시연] 양재 도보 경로에 결빙이 예상돼요`를 사용한다. 본문에는
  `양재역 4번 출구 → 양재동우체국. 눌러서 과거 예보로 계산한 안전 경로를 확인하세요.`를 표시한다.
- 기기 알림을 누르면 실제 과거 예보를 사용하는 양재역 4번 출구 → 양재동우체국
  경로 결과가 바로 열린다. 결과에서 기상 기준 시각과 출처를 확인할 수 있다.
- 기기 알림 권한과 잠금화면 표시 여부는 기기 설정을 따른다. 개인 경로 저장,
  보호자·복지관 공유, 실제 기상 조건에 따른 자동 발송은 이번 시연에서 제외한다.

## 11. 접근성 명세

### 11.1 시각 접근성

- 일반 텍스트 대비 최소 4.5:1
- 큰 텍스트와 핵심 그래픽·아이콘 대비 최소 3:1
- 색상 이외 아이콘·패턴·문구 병행
- 본문 최소 14sp, 기본 17sp
- 화면 확대와 200% 글자 크기에서 clipping·겹침·가로 스크롤 없음
- 이미지 속 텍스트를 UI 텍스트로 사용하지 않음
- 지도 위 텍스트에는 불투명 surface 또는 halo 제공

### 11.2 스크린 리더

- 모든 control에 accessible name, role, state 제공
- 아이콘 이름은 모양이 아니라 행동을 설명: `X 아이콘`이 아니라 `검색어 지우기`
- 장식용 눈꽃·배경 이미지는 접근성 트리에서 제외
- 경로 결과 갱신은 상태 메시지로 한 번 알리고 상세 내용은 사용자가 탐색
- 위험 marker를 개별 반복 낭독하기 전에 전체 개수와 경로 요약 제공
- 포커스 순서는 화면 제목 → 핵심 정보 → 주요 CTA → 보조 동작
- dialog가 열리면 포커스를 제목으로 이동하고 닫히면 실행한 control로 복귀

### 11.3 운동 능력과 입력 방식

- 모든 touch target 최소 48dp
- gesture-only action 금지
- drag, swipe, pinch에는 버튼 또는 목록 대안 제공
- Voice Access에서 보이는 라벨과 접근성 이름을 일치시킴
- Switch Access의 선형 포커스 순서가 시각 순서와 일치
- 중요한 작업은 시간 제한 없음

### 11.4 인지·학습 접근성

- 짧은 문장, 익숙한 단어, 한 문장 한 의미
- 화면마다 명확한 제목과 한 개의 주요 행동
- 단계와 현재 위치를 일관되게 표시
- 예측 가능한 뒤로가기와 취소 제공
- 오류는 원인 + 해결 방법으로 작성
- 자동으로 바뀌는 carousel, 깜박임, 주의를 빼앗는 장식 금지
- 사용자가 같은 정보를 반복 입력하지 않게 함
- 아이콘 단독보다 아이콘 + 텍스트 라벨을 우선

### 11.5 청각 접근성

- 음성 안내를 유일한 정보 채널로 사용하지 않는다.
- 모든 음성 정보는 화면 텍스트와 아이콘으로도 제공한다.
- 햅틱은 선택적 보조 수단이며 끌 수 있어야 한다.

### 11.6 저사양·네트워크 취약 사용자

- 장식용 대형 이미지와 과도한 blur를 피한다.
- 느린 네트워크에서 현재 진행 상태와 취소·재시도 동작 제공
- 이전 결과를 현재 결과처럼 조용히 재사용하지 않는다.
- 지도 로딩 실패 시 텍스트 결과 또는 명확한 오류를 제공한다.

## 12. Motion

- 기본 transition: 150~300ms
- 화면 전환에서 큰 zoom·parallax·회전 금지
- 경로가 그려지는 animation은 정보 이해에 필요할 때만 사용
- `Reduce motion` 설정에서 decorative animation을 제거
- 진행 상태는 무한한 화려한 animation보다 progress indicator + 텍스트 사용
- 초당 3회 이상 깜박이는 효과 금지

## 13. 반응형·큰 글자 대응

- mobile baseline 폭: 360dp 이상
- 폭이 좁으면 2열 요소를 1열로 전환
- 큰 글자에서 버튼 높이를 고정하지 않고 내용에 맞게 증가
- 텍스트를 말줄임표로 숨기기보다 container를 확장
- 지도 결과 sheet는 내용이 길어지면 내부 스크롤
- portrait만 강제하지 않으며 landscape에서도 주요 CTA와 상태가 접근 가능
- safe area와 system bar inset을 반영

## 14. 콘텐츠 스타일

### 14.1 문장 규칙

- 존댓말 사용
- 전문용어보다 일상어 사용
- `위험도 0.82` 대신 `결빙 위험 예상구간이 있어요`
- `API 오류` 대신 `기상 정보를 불러오지 못했어요`
- 사용자를 탓하지 않음
- 과도한 공포 표현 금지

### 14.2 용어 사전

| 사용 | 사용하지 않음 |
|---|---|
| 안전 경로 | 안전이 보장된 경로 |
| 결빙 위험 예상구간 | 결빙 확정 구간 |
| 자료 부족 | 안전함, 위험 없음 |
| 약 3분 추가 | 비용 증가, penalty |
| 과거 기상 재생 | 가상 날씨, 합성 날씨 |
| 다시 검색하기 | 실패, 잘못 입력함 |

## 15. 구현 금지 사항

- `DESIGN.md`에 없는 사용자용 내부 지표 추가
- 색상만으로 경로·위험·상태 구분
- 48dp 미만의 icon button touch target
- placeholder만 있는 input
- 지도만 제공하고 텍스트 대안 생략
- 자동으로 닫히는 중요한 오류
- 비활성 버튼만 보여주고 이유를 설명하지 않음
- 가독성을 해치는 glassmorphism·강한 blur·낮은 opacity
- 장식용 눈꽃이 텍스트·지도·포커스 표시를 가림
- 로그인 없는 MVP에 계정·내 정보 navigation 추가
- 구현하지 않은 즐겨찾기·이동 안내 화면 노출

## 16. 접근성·디자인 QA 체크리스트

### 자동 검사

- [ ] 텍스트 대비 4.5:1 이상
- [ ] 비텍스트 대비 3:1 이상
- [ ] touch target 48dp 이상
- [ ] accessible name/role/state 누락 없음
- [ ] heading과 focus order 검증
- [ ] 내부 계산 필드가 public UI에 없음

### 수동 검사

- [ ] TalkBack으로 출발지 입력부터 결과 확인까지 완료
- [ ] Switch Access 또는 키보드로 모든 동작 완료
- [ ] Voice Access에서 버튼 이름이 보이는 라벨과 일치
- [ ] 200% 글자 크기에서 clipping·겹침 없음
- [ ] 고대비/색각 이상 시에도 경로와 위험 구분 가능
- [ ] Reduce motion에서 불필요한 animation 제거
- [ ] 한 손 사용과 떨림 상황에서 주요 control 조작 가능
- [ ] 지도 없이도 경로 시간·위험·오류를 이해 가능
- [ ] 자료 부족과 낮은 위험을 혼동하지 않음
- [ ] 실제 고령 사용자 또는 디지털 취약 사용자 관점의 휴리스틱 리뷰 수행

### 화면별 확인

- [ ] 홈의 주요 CTA가 하나로 명확함
- [ ] 검색 결과 행 전체가 48dp 이상이며 라벨이 명확함
- [ ] 목적지 확인에서 출발지·목적지 수정 가능
- [ ] 결과에서 일반 경로, 안전 경로, 추가시간이 명확히 구분됨
- [ ] 위험 상세에 내부 강수량·점수 미노출
- [ ] 안전 경로를 찾지 못했을 때 이유와 다음 행동을 안내함
- [ ] P1 설정을 구현했다면 글자·음성·햅틱·motion 선택이 실제 반영됨

## 17. 완료 정의

디자인 구현은 다음 조건을 모두 만족해야 완료다.

- Material 3 component와 color role을 사용한다.
- 이 문서의 HEX token을 임의의 개별 색으로 대체하지 않는다.
- 예시 이미지의 핵심 분위기와 정보 계층을 유지한다.
- 승인된 화면별 구조를 구현한다.
- Android 접근성 및 WCAG 2.2 AA 수준의 핵심 기준을 만족한다.
- TalkBack, 큰 글자, touch target, 대비, color-independent 상태를 검증한다.
- 보행 경로와 위험 예상구간을 지도와 텍스트 모두로 이해할 수 있다.
- 안전 보장 표현과 내부 계산값 노출이 없다.

| 항목 | 최종 결정 |
|---|---|
| 로고 | P0는 텍스트 wordmark `빙빙제로` 사용, 별도 이미지 로고는 P1 |

| 고대비 지도 | 기본 경로 표현부터 고대비 적용, 별도 toggle은 P1 |
| 과거 자료 badge | `과거 기상 재생`으로 확정 |

| 화면 흐름 | 서울 지도 홈 → 장소 검색 → 지도와 하단 확인 시트 → 경로 비교 |
| component mapping | React responsive web + Material 3 semantic token |
